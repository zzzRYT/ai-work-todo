## Summary

회사 업무 할 일을 오늘/내일/백로그로 관리하고(P1), 러프한 문장을 AI가 깔끔한 할 일 후보로 정리해 사용자가 확인한 뒤 반영하며(P2),
AI가 오늘 계획안을 제안하고(P3), 스탠드업·정기 미팅 기록을 직접 남기고 할 일과 연결하는(P4~P5) **1인용 반응형 웹앱**이다.
PC·휴대폰 브라우저에서 같은 계정으로 쓰고 홈 화면에 추가할 수 있으며, 오프라인에서는 마지막으로 불러온 내용을 읽기만 한다(P6).

**기술 접근(제안)**: 캡틴 1명 전용이며, React + TypeScript + Vite로 만든 **PWA**가 **Supabase**(Postgres + RLS + Auth)를 직접 사용하고,
AI 호출은 **Supabase Edge Function 한 곳**에서만 수행한다(키·프롬프트·쿼터·검증이 서버에 있음). AI는 구조화된 JSON을 **제안**으로만 돌려주고,
사용자가 확정하면 **원자적 RPC**가 할 일을 만든다. 목록(오늘/내일/백로그/밀린 일)은 저장하지 않고 `plan_date` 하나에서 **읽을 때 계산**해서 자정 배치 작업이 없다.
정적 파일은 캡틴 도메인의 서브도메인(`<sub>.jinjinstar.com`)으로 Cloudflare Pages 에서 서비스하고, 백엔드는 Supabase 무료 플랜으로 시작한다. AI 는 캡틴의 Anthropic 키(월 $100 크레딧)로 **Sonnet 5.5**를 기본 사용하며 평소 월 약 $5, **앱 월 상한 $20**으로 막는다.

## Technical Context

**Language/Version**: TypeScript 5.x (프론트엔드, Edge Function은 Deno 런타임의 TypeScript), SQL(Postgres) 마이그레이션. 정확한 버전은 스캐폴딩 시 최신 LTS/안정 버전으로 고정.

**Primary Dependencies**: React, Vite, vite-plugin-pwa(Workbox), TanStack Query(+ persist 어댑터, `idb-keyval`), `@supabase/supabase-js`, Zod(AI 응답·폼 검증), Anthropic API(Messages API, 구조화 출력). UI/스타일 라이브러리는 화면 디자인 단계에서 결정.

**Storage**: Supabase Postgres(원본 데이터), 브라우저 IndexedDB(오프라인 읽기용 캐시). 자세한 스키마는 [data-model.md](./data-model.md).

**Testing**: Vitest + Testing Library(단위/컴포넌트), Playwright(종단, 휴대폰 뷰포트 포함), Supabase 로컬 스택 + pgTAP(RLS·제약), AI 계약 테스트(가짜 제공자) + 수동 실행 평가 스크립트(한국어 표본).

**Target Platform**: 최신 데스크톱 브라우저(Chrome/Edge/Safari/Firefox)와 휴대폰 브라우저(iOS Safari, Android Chrome); 홈 화면 추가(PWA).

**Project Type**: web-application (SPA 프론트엔드 + 매니지드 백엔드; 자체 서버 프로세스 없음)

**Performance Goals**: SC-001 앱 열고 10초 내 할 일 추가, SC-002 자유 문장 정리 30초 내 확인·반영, SC-005 아침 계획 2분, SC-007 다른 기기 반영 5초 내(재조회), SC-011 오프라인 5초 내 열기. AI 응답은 보통 수 초(타임아웃 25초).

**Constraints**: 1인 전용 개인 프로젝트 → 호스팅·DB 고정비는 0에 가깝게, AI 월 지출은 크레딧($100)의 20% 이내, 운영 대상 최소화, 오프라인 편집 없음, 알림·외부 연동·스토어 배포 없음(스펙 Assumptions), 한국어 UI·한국어 AI 우선, 공개 저장소(비밀값 커밋 금지).

**Scale/Scope**: 사용자 1명(캡틴; RLS 는 방어선으로 유지), 열린 할 일 수백~수천 건, 미팅 기록 연 수백 건, AI 요청 하루 최대 40회(제안). 주요 화면 약 8개(오늘/내일/백로그, AI 입력·미리보기, 오늘 계획, 스탠드업, 정기 미팅·회차, 검색/완료 기록, 설정, 로그인) — 시각 설계는 다음 단계.

```text
┌────────────────────────────┐          ┌──────────────────────────────────────────┐
│ 브라우저 / 홈 화면 PWA     │          │ Supabase (매니지드)                      │
│  React SPA (정적 파일)     │ HTTPS    │  Auth ── JWT ─┐                          │
│  ├ 서비스 워커: 앱 셸 캐시 │─────────▶│  PostgREST ◀──┴─ RLS(user_id=auth.uid()) │
│  ├ TanStack Query 캐시     │  CRUD    │  Postgres: tasks, standups, …            │
│  │   └ IndexedDB(읽기전용) │          │  RPC: apply_ai_*, create_task_from_*, …  │
│  └ 목록 계산(plan_date,TZ) │  AI 요청 │  Edge Function `ai` ──────┐              │
└────────────────────────────┘─────────▶│  Edge Function `delete-account`          │
        ▲ 정적 호스팅                    └───────────────────────────┼──────────────┘
        │                                  키(서버 비밀값)·프롬프트·쿼터·월 예산 │ 구조화 출력(JSON)
  Cloudflare Pages                                                  ▼
  https://<sub>.jinjinstar.com                      AI 제공자 (Anthropic Messages API)
  (커스텀 서브도메인, 상세: deployment.md)
```

- 일반 CRUD 는 브라우저 → Postgres(RLS) 직행. **서버가 필요한 곳은 AI(비밀 키)와 계정 삭제(관리자 권한)뿐.**
- 같은 계정의 여러 기기는 같은 DB 를 보고, 재조회로 동기화한다(SC-007).
- 오프라인: 서비스 워커가 앱을 열어 주고, IndexedDB 에 저장된 쿼리 캐시를 읽기 전용으로 보여 준다(FR-028).

## AI 동작 설계

AI 기능은 스펙대로 **할 일 정리(FR-009~013)와 오늘 계획(FR-014) 두 가지뿐**이며, 미팅 기록은 읽거나 쓰지 않는다(FR-017). 요청/응답 형태는 [contracts/ai-api.md](./contracts/ai-api.md)와 [contracts/schemas/](./contracts/schemas/).

### 흐름 (제안 → 미리보기 → 확정)

```text
사용자 입력(또는 '오늘 계획' 버튼)
  → [온라인? 동의했나? 한도 남았나?]  아니오 → 안내만 표시, 입력 원문 유지
  → Edge Function: 최소 컨텍스트 조립 → AI 호출(구조화 JSON) → 서버가 검증·정제
  → 클라이언트: "제안 미리보기" (이 시점까지 tasks 변경 없음 — ai_requests 에 proposed 로만 기록)
       · 후보별로 제목/설명/목록/마감일/하위 할 일 편집, 체크 해제로 제외
       · 추정(inferred) 값은 "추정" 표시, 근거 문구(due_quote) 표시
  → [확정] → apply_ai_* RPC(원자적, 멱등) → 선택/수정된 항목만 반영
  → [닫기] → discard_ai_request → 아무 것도 바뀌지 않음
```

### AI가 받는 것 / 돌려주는 것

| 기능 | AI가 받는 것 | 구조화 출력 | 사용자 확인 |
|------|--------------|-------------|-------------|
| 정리 (FR-009~011) | 사용자가 입력한 문장 + 현재 날짜·요일·시간대(서버 계산) | 후보 배열: 제목, 설명, 하위 할 일, 목록(today/tomorrow/backlog/unspecified), 마감일, 마감 근거(explicit/inferred/none)와 인용 문구 | 후보 편집·제외 후 확정한 것만 생성 |
| 다듬기·쪼개기 (FR-013) | 대상 할 일 **하나**(제목·설명·기존 하위 할 일) + 사용자의 지시문 | 새 제목/설명, 추가할 하위 할 일 | 부분 선택 적용, 그 사이 수정되면 충돌 안내 |
| 오늘 계획 (FR-014) | 후보 할 일 최대 80개(제목·목록·밀림 여부·마감까지 일수·우선순위, **임의 ref 로 표기**) + 오늘 정기 미팅 이름·시각 | 선택한 ref 와 항목별 짧은 이유, 요약 | 항목별 선택 후 승인한 것만 `plan_date=오늘` |

### 환각·근거 통제 (FR-011, FR-015, SC-004)

- 날짜 표현 변환은 **서버가 계산한 오늘 날짜·요일·시간대를 프롬프트에 넣어** 모델이 실제 날짜를 만들고, 서버가 형식·범위를 검증한다.
- 스키마에 `due_basis`(explicit/inferred/none)와 `due_quote`를 두고, **explicit 인데 인용 문구가 원문에 없으면 서버가 inferred 로 강등** → 화면에 "추정" 표시. 원문에 근거 없는 값은 빈 값으로 둔다.
- 오늘 계획은 **서버가 만든 후보 풀 안의 ref 만** 선택 가능하고 풀 밖 ref 는 버린다. AI는 할 일을 새로 만들거나 삭제할 수 없다. 도구(tool) 호출을 주지 않는다.
- 정확도 목표(SC-003 제목 90%, SC-004 날짜 95%)는 **표본 문장 평가 스크립트**로 측정한다. 표본 세트가 스펙에 없으므로 구현 단계에서 만들어야 한다([스펙 갭](#스펙-갭-스펙은-수정하지-않음) 9).

### 실패·오프라인 동작 (FR-016, FR-028, SC-010)

| 상황 | 동작 |
|------|------|
| 오프라인 | AI 버튼 비활성 + "연결이 필요해요" 안내. 서버 호출 없음 |
| 제공자 오류/타임아웃(25초)/거절/스키마 불일치 | 서버가 필요 시 1회 재시도 → 실패하면 오류 코드 반환. 입력창 원문 유지, "다시 시도" 와 "직접 추가" 제공 |
| 후보 0개 | 아무것도 만들지 않고 이유 표시, 다시 입력/직접 추가 안내 |
| 한도 초과 | "오늘 AI 사용 한도에 도달했어요" + 직접 추가. 남은 횟수는 항상 표시 |
| 월 예산 상한 도달(`monthly_budget_exceeded`) 또는 제공자 지출 한도·크레딧 소진(`provider_budget_exhausted`) | AI 버튼만 비활성 + "이번 달 AI 예산을 다 썼어요", 다음 달 1일 재개 안내. 직접 입력 정상 |
| AI 전체 장애/비활성(`AI_ENABLED=false`) | AI 버튼만 비활성. 할 일·미팅 기능은 영향 없음(AI 코드 경로와 분리) |
| 응답 후 확정 전에 앱 닫기/만료(24시간) | 아무 변경 없음. 제안은 만료 처리 |

### 비용·한도 통제 (캡틴 예산: 월 $100 크레딧)

가격은 [Anthropic Pricing](https://platform.claude.com/docs/en/about-claude/pricing) 2026-10-24 확인: Sonnet 5.5 입력 $2 / 출력 $10, Haiku 5.5 입력 $0.10 / 출력 $0.50 (백만 토큰당). 크레딧 조건은 2차 출처만 확인했다([research D5](./research.md#d5-ai-제공자와-모델)).

- **기본 모델 Sonnet 5.5**: 요청당 정리 약 $0.012, 다듬기 약 $0.009, 오늘 계획 약 $0.031. **평소 사용(하루 10회 안팎)은 월 약 $5**, 많이 써도(하루 40회 상한) 약 $20. Haiku 5.5 로 바꾸면 약 1/20. 모델은 `AI_MODEL` 한 줄로 교체.
- **겹겹의 상한** (안쪽 → 바깥쪽, 모두 크레딧 $100 보다 한참 아래):
  1. 일일 요청 **40회** (`AI_DAILY_REQUEST_LIMIT`)
  2. 앱 월 상한 **$20** (`AI_MONTHLY_BUDGET_USD`; 서버가 토큰×가격으로 계산, 넘으면 AI만 차단)
  3. Console **앱 전용 워크스페이스** 지출 한도 **$30** (제공자 쪽 안전망)
  4. Console **조직** 지출 한도 **$50**
  5. 크레딧 $100 (이월 없음)
- 입력 4,000자, 후보 80개, 고정 `max_tokens`, 재시도 1회, 멱등 키로 중복 과금 방지, `AI_ENABLED` 킬 스위치는 유지.
- 모든 요청의 토큰 수·추정 비용을 `ai_requests` 에 기록해 실제 비용을 확인하고(구현 직후 1~2주 관찰해 한도 조정), 설정 화면에 이번 달 사용 %를 보여 50%·80% 에서 안내한다.
- 크레딧은 이월되지 않는다고 보도되었으므로(미확인), "남기는 것"보다 **품질을 위해 쓰는 쪽**이 합리적이다 → Sonnet 기본의 근거.
- 1인 전용이므로 타인이 키 비용을 쓰는 경로는 없다(가입 끔, JWT 필수, CORS 한 곳).

### 개인정보: 업무 정보를 AI 제공자에게 보내는 문제

> 이 앱은 **회사 업무 정보**를 외부 AI 서비스로 보낸다. 기술적 통제로 줄일 수는 있지만 **소속 회사의 보안·AI 사용 정책이 허용하는지는 사용자가 판단**해야 한다. 캡틴 확인 사항으로 PR에 명시한다.

1. **명시적 요청 때만 전송**: AI 버튼을 눌렀을 때만. 백그라운드·자동 전송 없음(스펙 Assumptions).
2. **첫 사용 동의(버전 관리)**: 무엇이, 어디로(제공자 이름), 얼마나 보관되는지 알리고 동의를 `profiles.ai_consent_version` 에 저장. 서버가 동의 없는 요청을 403 으로 거절. 고지 내용을 바꾸면 버전을 올려 재동의. 설정에서 동의 철회(=AI 끔) 가능.
3. **최소 전송 원칙**
   - 정리: 사용자가 입력한 문장만. 계정·이메일·기존 할 일·미팅 내용 없음.
   - 다듬기: 선택한 할 일 한 건만.
   - 오늘 계획: 할 일 **제목과 메타 정보만**(설명·하위 할 일·라벨 제외), UUID 대신 임시 ref, 오늘 정기 미팅 **이름과 시각만**. **미팅 기록·스탠드업 내용은 어떤 경우에도 보내지 않음.**
   - 사용자 식별자(이메일, user_id)는 요청 본문에 넣지 않는다.
4. **투명성**: 오늘 계획 화면에 "이번에 보낸 내용"(할 일 N개 제목 + 미팅 이름)을 표시하고, 동의 대화상자에 항목별로 나열.
5. **제공자 측 보관**: Anthropic API 기본값은 입력·출력을 30일 이내 삭제하고, 문서상 보관 데이터를 명시적 허락 없이 학습에 쓰지 않는다(출처·확인일은 research D5). ZDR 은 신청 필요. 크레딧으로 쓰는 키가 같은 상업용 API 경로로 처리되는지는 공식 확인을 못 해 **캡틴이 Console 에서 확인**해야 한다. 반면 **Gemini 무료 티어는 입력이 제품 개선과 사람 검토에 쓰일 수 있어 업무 정보에 부적합**.
6. **우리 쪽 보관**: 함수 로그에 본문 금지. `ai_requests` 의 원문·제안은 확정/폐기 30일 후 비움, 사용량 열만 유지. 계정 삭제 시 전부 삭제.
7. **출력 안전**: AI 출력은 도구 없이 텍스트→검증된 필드로만 사용되고, 사용자가 만든 문장 내 지시문이 DB 를 바꾸지 못한다(쓰기는 사용자 확정 RPC 만).
8. **API 키 취급**: 키는 Supabase Edge Function 비밀값에만 존재한다. 저장소·로그·브라우저 번들·PR·채팅에 두지 않고, 함수 로그에 요청 헤더·본문을 남기지 않으며, 빌드 산출물 스캔과 CI 비밀값 스캔으로 확인한다. 노출이 의심되면 Console 에서 폐기·재발급. 보관 위치와 절차는 [deployment.md §6](./deployment.md#6-비밀값-anthropic-api-키).
9. **기기 내 캐시**: 오프라인 캐시는 IndexedDB 평문. 로그아웃 시 삭제, "이 기기 캐시 지우기" 제공. 공용 PC 사용은 비권장 안내.

## 스펙 갭 (스펙은 수정하지 않음)

계획 중 발견한 모호함/누락. 스펙은 고정됐으므로 여기 기록만 하며, 계획의 임시 가정을 함께 적었다.

1. ~~**FR-026/027 가입 범위**~~ **해소됨(2026-10-24)**: 캡틴이 "혼자 사용"으로 확정. 가입 닫음, 사용자별 공유·쿼터 없음. (스펙 문구 자체는 수정하지 않음 — 스펙은 이미 1인 개인용을 요구하고 있어 충돌 없음.)
2. **AI 사용 한도**: 스펙에 횟수·크기·예산 한도가 없음(비용 통제 필요). → 하루 40회, 월 $20, 입력 4,000자 제안(캡틴 예산 월 $100 크레딧 기준).
3. **AI 요청 기록 보존**: Key Entity 가 원문·제안·결과를 두는데 보존 기간이 없음. → 30일 후 원문·제안 비움 제안.
4. **FR-004 여러 날 비운 경우**: "내일"에 둔 일을 며칠 열지 않았을 때(plan_date 가 이틀 이상 과거)는 시나리오에 없음. → 오늘 목록의 밀린 일로 표시.
5. **오프라인 캐시 범위·기한(FR-028)**: "마지막으로 불러온 내용" 중 오래된 완료 기록·미팅 기록을 어디까지 포함하는지, 캐시를 얼마나 오래 유지하는지 불명확. → 열린 할 일 전부 + 완료 30일 + 미팅/스탠드업 90일.
6. **FR-008 "직후" 되돌리기 시간**: 지속 시간 불명확. → 10초 토스트 + 30일 소프트 삭제.
7. **FR-014 "오늘 예정된 미팅" 범위**: 정기 미팅은 요일만 있고 시각이 없으며, 매일 스탠드업의 일정/시각은 정의되지 않음. → 정기 미팅에 선택적 시작 시각 추가, 스탠드업은 AI 입력에서 제외.
8. **FR-003 "라벨/프로젝트"**: 같은 개념인지 별개인지 불명확. → 라벨 하나로 통합. 우선순위 단계 수도 미정 → 4단계.
9. **SC-003/SC-004 측정용 표본**: 90%/95% 를 재려면 한국어 표본 문장·정답 세트가 필요한데 없음. → 구현 단계에서 작성(작성 주체 결정 필요).
