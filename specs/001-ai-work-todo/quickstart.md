# Quickstart: 검증 가이드

**Plan**: [plan.md](./plan.md) | **Contracts**: [contracts/](./contracts/) | **Data model**: [data-model.md](./data-model.md)

구현이 끝났을 때 기능이 처음부터 끝까지 동작하는지 확인하는 **실행/검증 절차**입니다. 구현 코드나 테스트 본문은 여기에 두지 않습니다(작업 분해는 tasks, 계약은 contracts).
아래 명령은 스캐폴딩 작업이 끝난 뒤의 **목표 형태**이며, 지금(계획 단계)은 아직 실행할 수 없습니다.

## 준비물

- Node.js LTS, 패키지 매니저(npm), Docker(Supabase 로컬 스택용), Supabase CLI
- AI 실제 호출을 확인하려면 AI 제공자 API 키(**로컬 환경 변수 파일에만**, 커밋 금지)
- 변수 이름은 `.env.example` 참고 — 값은 저장소에 없다. 필요한 이름: `ANTHROPIC_API_KEY`, `AI_MODEL`, `AI_ENABLED`, `AI_DAILY_REQUEST_LIMIT`, `AI_MAX_INPUT_CHARS`, `PLAN_POOL_MAX`, `AI_CONSENT_VERSION`, 프론트엔드용 `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`

## 로컬 실행 (목표 형태)

```text
supabase start                      # 로컬 Postgres/Auth/함수 런타임
supabase db reset                   # 마이그레이션 + seed 적용
supabase functions serve ai --env-file <로컬 env 파일>
npm --prefix web install && npm --prefix web run dev
```

## 자동 검증

```text
npm --prefix web run typecheck && npm --prefix web run lint
npm --prefix web test               # 날짜 계산, 컴포넌트
supabase test db                    # pgTAP: RLS, 제약, RPC
npm --prefix web run e2e            # Playwright (데스크톱 + 작은 휴대폰 뷰포트)
```

AI 계약 테스트(가짜 제공자)는 위 단위 테스트에 포함된다([contracts/ai-api.md](./contracts/ai-api.md#계약-테스트-항목-구현-시-자동화) 7항목).
실제 모델 평가는 **수동 실행**: 표본 문장 세트를 돌려 SC-003(제목 수정 없이 확정 ≥90%)·SC-004(날짜 정확 ≥95%)를 측정하고 결과를 기록한다. 미달이면 `AI_MODEL` 을 올려 재측정.

## 수동 검증 시나리오

각 시나리오는 스펙의 사용자 스토리/성공 기준에 대응한다.

| # | 시나리오 | 확인할 것 | 스펙 |
|---|----------|-----------|------|
| 1 | 로그인 → 제목만 입력해 할 일 추가 → 완료 → 내일/백로그로 이동 → 되돌리기 | 즉시 반영, 완료 목록에서 다시 보기, 삭제/완료 되돌리기, 앱 열고 10초 내 추가 | US1, FR-001~008, SC-001 |
| 2 | 시스템 시계/시간대를 하루 뒤로 바꿔 앱 열기 (또는 `plan_date` 를 전날로 seed) | 내일 항목이 오늘로, 어제 미완료 오늘 항목이 "밀린 일"로 표시 | FR-004, FR-029 |
| 3 | 켜 둔 채 자정 통과 (시계 조작) | 새로고침 없이 목록 재계산 | Edge case |
| 4 | 처음 AI 사용 → 동의 대화상자 → 거절하면 AI 호출 0회, 직접 입력은 정상 | 동의 전 서버 403, 전송 항목 안내 문구 | Assumptions, FR-016 |
| 5 | 자유 문장 입력 → 후보 미리보기 → 하나 수정·하나 제외 후 확정 | 확정 전 목록 변화 없음, 확정한 것만 생성, "추정" 표시, 상대 날짜가 시간대 기준 실제 날짜 | US2, FR-009~012, FR-015, SC-002 |
| 6 | 기존 할 일에서 "더 구체적으로 나눠 줘" → 일부만 적용 | 하위 할 일 추가, 다른 기기에서 먼저 수정했다면 충돌 안내 | FR-013 |
| 7 | AI 오류 상황 (함수를 중단 / 가짜 제공자가 오류 / 한도 초과 / 오프라인) | 입력 원문 유지, 직접 추가 안내, 나머지 기능 정상 | FR-016, SC-010 |
| 8 | 오늘 계획 요청 → 항목별 이유 → 일부만 승인 / 닫기 | 승인 항목만 오늘로, 닫으면 변화 없음, "보낸 내용" 요약 표시, 미팅 기록 내용 미전송 | US3, FR-014, FR-017 |
| 9 | 스탠드업 작성 → 막힌 점 문장을 할 일로 → 스탠드업 삭제 | 어제 완료/오늘 목록 참고 표시, 양방향 이동, 삭제 후 할 일 유지 | US4, FR-018~021 |
| 10 | 정기 미팅 등록 → 회차 2회 기록 → 액션 아이템을 할 일로 → 다음 회차 열기 | 지난 회차 요약·미완료 액션 아이템 표시, 건너뜀 표시 | US5, FR-020~023 |
| 11 | 다른 기기(또는 다른 브라우저 프로필)에서 같은 계정 로그인 | 새로 열기/새로고침 5초 내 반영 | US6, FR-026, SC-007 |
| 12 | 작은 휴대폰 뷰포트에서 추가·완료·이동·AI 정리·미팅 기록 | 가로 스크롤/확대 없이 완료 | FR-024, SC-008 |
| 13 | 휴대폰에서 홈 화면에 추가 후 실행 | 주소창 없이 앱처럼 열림. **iOS 에서 홈 화면 앱과 Safari 의 로그인 세션이 따로인지 확인(미확인 항목)** | FR-025 |
| 14 | 비행기 모드로 앱 열기 → 보기만 되고 편집/AI 차단, 마지막 불러온 시각 표시 → 연결 복구 | 읽기 전용 안내, 세션 만료 때문에 로그아웃되지 않음, 작성 중 입력 유지, 복구 후 최신 내용 | FR-028, SC-011, Edge cases |
| 15 | 한 번도 불러온 적 없는 기기에서 오프라인으로 열기 | 연결 필요 안내 | Edge case |
| 16 | 설정에서 내보내기 → JSON 확인, 계정 삭제 → 로그인·데이터 전부 사라짐 | 형식은 [data-model.md](./data-model.md#내보내기-형식-fr-030) | FR-030 |
| 17 | 다른 계정으로 로그인해 첫 계정의 행 id 로 직접 조회/수정 시도 | 모두 거부(RLS) | FR-027 |
| 18 | 로그아웃 | 기기 캐시(IndexedDB) 삭제 | 개인정보 |

## 완료 기준 (이 계획 → 구현)

- 위 자동 검증이 모두 통과한다.
- 시나리오 1~18을 실행한 결과가 PR 설명에 기록된다.
- 계획의 가정 중 확인되지 않은 것(iOS 세션 분리, 장기 오프라인 캐시, Haiku 5.5 한국어 품질)의 결과가 [research.md](./research.md) 의 미해결 표에 반영된다.
